# Spec: `/apply` — Private AI Job-Application Assistant

Date: 2026-07-24
Status: Approved for implementation

## Purpose

A private, unlisted page at `/apply` — never linked from the portfolio (nav, footer,
sitemap) and not indexable — where the owner pastes a job description and gets a
tailored job-application artifact generated by OpenAI, grounded in their real
portfolio background. Chat-style and multi-turn so answers can be refined.

Only the owner should reach it: hidden URL **plus** a passcode gate (protects the
OpenAI credits the page spends).

## Behaviour

- **Adaptive output.** The assistant produces whatever the user's message asks for
  (cover letter, short outreach message, tailored resume bullets, screening-question
  answers, …). If no format is specified, it defaults to a concise, tailored cover
  letter. Scope is limited to job-application material.
- **Grounded.** It uses ONLY the owner's real background (experience, skills,
  projects, contact) as candidate context and must not invent employers, roles, or
  skills.
- **Multi-turn + streaming.** Follow-ups ("make it shorter", "more formal") work
  because the full message thread is re-sent each request. Responses stream token by
  token.

## Access / Security

- Route excluded from nav, footer, and `sitemap.ts`. Page metadata: `robots: { index:
  false, follow: false }`. `robots.ts` adds `disallow: '/apply'`.
- Passcode gate: a lock screen collects a passcode, verified server-side against the
  `APPLY_PASSCODE` env var. On success the passcode is kept in `sessionStorage` and
  sent in an `x-apply-key` header with every request. No cookie/session machinery
  (personal tool, HTTPS). The server rejects any chat request whose header does not
  match. `APPLY_PASSCODE` and `OPENAI_API_KEY` live only in server env; neither is
  ever shipped to the browser.
- No extra rate limiting beyond the passcode (single-user tool). Add later if needed.

## Architecture

```
src/app/apply/page.tsx         Server component: noindex metadata + renders <ApplyClient/>
src/app/apply/apply-client.tsx Client: lock screen + chat UI, streaming fetch, copy
src/app/api/apply/route.ts     POST: verify passcode; build system prompt; stream OpenAI
src/lib/apply-profile.ts       Server util: portfolio data -> candidate-profile text
src/app/robots.ts              + disallow '/apply'
```

### `apply-profile.ts`
Pure function `buildCandidateProfile(): string` that composes a plain-text profile
from `experiences`, `skillCategories`, `projects`, and `constants` (name, location,
links). No secrets. Deterministic — unit-testable.

### `api/apply/route.ts` (POST)
- Reads passcode from `x-apply-key` header; compares to `APPLY_PASSCODE`. Missing/
  mismatch → `401`.
- Body `{ verify: true }` → passcode-only check, returns `{ ok: true }` (used by the
  lock screen for instant feedback). No OpenAI call.
- Body `{ messages: {role,content}[] }` → builds `system` prompt (instructions +
  candidate profile), prepends it, and calls OpenAI
  `POST https://api.openai.com/v1/chat/completions` with `stream: true` via `fetch`
  (no new dependency). Model from `OPENAI_MODEL` (default `gpt-4o-mini`).
- Parses the upstream SSE, extracts `choices[0].delta.content`, and re-streams plain
  text chunks to the client via a `ReadableStream`.
- Missing `OPENAI_API_KEY` → `500` with a friendly message. Upstream OpenAI errors →
  surfaced as a readable message.

### `apply-client.tsx`
- On mount, reads `sessionStorage` passcode; if present, shows chat optimistically.
- Lock screen: passcode input → `POST {verify:true}` with header → on `ok`, store +
  unlock; on `401`, show "wrong passcode".
- Chat: message list, a textarea for the job description / instruction, Send. On send,
  append the user message, POST the full thread with the header, read the streamed
  text, and append it into a live assistant message.
- Copy button per assistant message. Basic states: sending/disabled, error banner.
- Design implemented with the `ui-ux-pro-max` skill; styled to the site's blueprint
  theme (engineering grid, mono/handwritten type, amber accent).

## Env

- `OPENAI_API_KEY` (required for generation), `APPLY_PASSCODE` (required to unlock),
  `OPENAI_MODEL` (optional, default `gpt-4o-mini`). All already present in
  `.env.local`; `.env*` is gitignored.

## Testing / QA

- Unit: assert `buildCandidateProfile()` includes the owner's name and at least one
  known company/skill (fails if data wiring breaks).
- Manual QA (screenshots): lock screen; wrong passcode rejected; unlocked empty chat;
  a real streamed generation from a pasted job description; copy button; missing-key
  error path.

## Out of scope

- Saving/history of past applications, PDF export, multi-user accounts, rate limiting.
  Can be added later.
